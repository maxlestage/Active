Short answers to the questions people ask most, with links to the pages that go further.

## What is active, in one sentence?

A small Rust library for building the front end of websites: components are functions, state lives in `use_state` handles, every page gets complete SEO tags, and the interactive parts run as WebAssembly, on server-rendered pages, static sites or client-side apps. See the [Introduction](../introduction/).

## Why not Leptos, Dioxus, Yew or Sycamore?

They are excellent, larger projects, and the better choice in some cases:

- **Leptos** is a full-stack framework: fine-grained reactivity, a `view!` macro, server functions, a router and an islands mode.
- **Dioxus** targets the web, desktop and mobile from one code base, with its `rsx!` macro.
- **Yew** and **Sycamore** are established component frameworks for the browser, with server rendering support.

`active` makes different trade-offs:

- **No macros.** Views are plain function calls, so rust-analyzer, rustfmt and compiler errors work everywhere, and there is no syntax to learn.
- **Server rendering first.** Complete HTML on every page, islands only where needed; a page without islands ships no code.
- **SEO built in.** Title, description, canonical, `hreflang`, Open Graph, Twitter and JSON-LD from one builder, with automatic [merging](../seo/#merging) across layouts and pages, on the server and in client-side apps.
- **Small.** A short API you can read in an afternoon ([API reference](../api/)), no dependencies on the server.

Choose a larger framework if you need server functions, desktop or mobile targets, or a big ecosystem of ready-made components. The [Benchmarks](../benchmarks/) page compares sizes and render times.

## Do I need to write JavaScript?

No. Components, server, build and tests are Rust. The browser receives two pieces of JavaScript that you never write or edit: the loader generated by `wasm-bindgen`, and one `<script type="module">` line written by [`Document::client`](../documents/#loading-the-browser-bundle) to start it. Browser APIs are available from Rust through [`web-sys`](https://docs.rs/web-sys) (see [Events](../events/#web-sys)).

## Does a page work with JavaScript disabled?

Its content does: server-rendered and static pages are complete HTML, so text, links and images work without any script. Islands stay as the HTML the server rendered, but do not react, since starting WebAssembly requires the loader. Forms with a real `action` and `method` keep working as plain HTML forms (see [Events](../events/#submitting-a-form)). A client-side app, on the other hand, needs scripts to show anything.

## Is a single-page app good for SEO?

Less than server-rendered pages. Google can run scripts and index content built in the browser, but later and less reliably than plain HTML, and most other crawlers and link-preview bots (social networks, chat apps) read only the HTML they receive. A client-side app sends a shell, so they see only the shell's title and description.

For public pages, use [server-rendered pages with islands](../islands/) or a [static site](../static-site/). If you need a client-side app and SEO, render each URL's first page on the server (see [Client-side apps](../client-app/#rendering-the-first-page-on-the-server)): the HTML then has the right title and tags, and the app takes over in the browser.

## What is a hydration mismatch?

When the browser hydrates an island, it expects the HTML from the server to match the view it builds itself. If they differ, it prints `active: re-rendering island (… mismatch)` in the console and rebuilds the island from scratch. The usual cause is a view that depends on something only one side has (the time, a random number, data from a database): pass everything the island needs in its props. Details and fixes: [Islands, Hydration mismatches](../islands/#hydration-mismatches).

## How do I load data asynchronously?

- **On the server:** await your database or API calls first, then build and render the view in one synchronous call, without any `.await` in between (the compiler rejects a `State` kept across an `.await` in a multi-threaded server). See [Axum, Async data](../axum/#async-data).
- **In the browser:** start a future with `wasm_bindgen_futures::spawn_local` from a handler or an effect, and write the result into a state; the view updates. See [Events, Async work in handlers](../events/#async-work-in-handlers).

Components themselves are synchronous functions.

## Is there a router?

On the server, use your web framework's router (Axum routes in the [Axum](../axum/) guide), one page function per route. In a client-side app, `active::location()` gives the current path as a state and handles links and the back button, `active::query()` and `active::query_param("q")` give the query string, and `active::navigate()` changes page from code. See [Client-side apps, Routing](../client-app/#routing).

## How do I style components?

With regular CSS. Add stylesheets with `Document::stylesheet("/static/app.css")`, set classes with `.class(...)`, toggle them with `.class_if(...)`, and use `.style(...)` for one-off inline styles or CSS variables (`.style(format!("--progress:{p}%"))`). Any CSS tool that produces a `.css` file works alongside. Inline `<style>` blocks can go in `Document::head(...)`.

## How big is the WebAssembly?

About 22 kB gzipped (57 kB raw) for a page with one counter island, 47 kB gzipped for the complete to-do app in `examples/spa`, built with the size-optimized profile and served compressed. Static content adds nothing, and each additional island adds only its own code. Numbers, settings and tips: [Performance](../performance/#sizes).

## How much does it cost to host on Heroku?

Heroku has no free tier. At the time of writing, the cheapest option, Eco dynos, costs about $5 per month (they sleep after 30 minutes without traffic), and a Basic dyno about $7 per month. See [Deploy to Heroku, Costs](../deploy-heroku/#costs). A [static site](../static-site/) can be hosted for free on GitHub Pages, Netlify or Cloudflare Pages.

## What is the crate called?

`active`, on [crates.io](https://crates.io/crates/active), with the documentation on [docs.rs/active](https://docs.rs/active). Until the first version is published there, depend on the repository: `active = { git = "https://github.com/maxlestage/Active" }`. The [Publishing](../publishing/) page explains how releases are made.

## Which Rust version do I need?

Rust 1.85 or newer: the crate uses the 2024 edition, declared as `rust-version = "1.85"`. Update with `rustup update`.

## Can I use it with Actix Web, Rocket or another server?

Yes. `Document::render()` returns a `String`: send it with the `text/html; charset=utf-8` content type from any framework. The [Axum](../axum/) guide shows one integration, and `examples/hello` uses only the standard library. A `Seo` can also be used on its own in any template.

## How do I see panic messages from the browser?

With the `wasm-release` profile, a panic stops the module and the console shows only a generic error. While developing, install a panic hook that prints the message: add `console_error_panic_hook = "0.1"` to the `wasm32` dependencies and call `console_error_panic_hook::set_once()` at the start of your `#[wasm_bindgen(start)]` function. A debug build also gives better messages (see [Building the client](../client-build/#faster-builds-while-developing)).

## Is it ready for production?

`active` is young (version 0.1). The API is small and tested, and this website runs on it, but it may change before 1.0. Pin the version in `Cargo.toml` and read the release notes when you upgrade. Issues and contributions are welcome on [GitHub](https://github.com/maxlestage/Active).
