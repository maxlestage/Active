Two functions cover WebAssembly in active-react: `wasm()` declares a module, `useWasm()` uses it in a component. This page covers both, plus preloading, errors and the less common ways to load.

## Declare a module

Declare each module once, in its own file, and import it wherever you need it:

```ts
// src/wasm.ts
import { wasm } from "active-react";
import url from "./pkg/hello_bg.wasm?url";

export const hello = wasm(() => import("./pkg/hello.js"), { url });
```

- The first argument is a function that imports the glue generated by wasm-bindgen or wasm-pack. Because it's a dynamic `import()`, your bundler puts the glue in a separate chunk.
- `url` is the public URL of the `.wasm` binary. It is optional, but it enables the preload described below.

**Nothing is fetched at this point.** Declaring modules is free, so you can declare as many as you like.

## Use it in a component

```tsx
import { useWasm } from "active-react";
import { hello } from "./wasm";

function Stats({ data }: { data: Float64Array }) {
  const rust = useWasm(hello);
  if (!rust) return <p>Loading…</p>;
  return <p>Mean: {rust.mean(data)}</p>;
}
```

`useWasm(mod)` returns the module's exports, or `undefined` while it is loading:

- The first component that calls it starts the download. Every other component shares the same request: the module is fetched, compiled and initialized **once** for the whole app.
- When loading finishes, every component using it re-renders with the exports.
- Once loaded, later components get the exports on their first render, with no loading state.
- It always returns `undefined` on the server and during hydration, so server and client markup match. See [server rendering](../server-rendering/#hydration-and-webassembly).

## Typed exports

The exports are typed from the `.d.ts` file wasm-bindgen generates next to the glue. If your Rust function is `pub fn mean(values: &[f64]) -> f64`, then `rust.mean` is `(values: Float64Array) => number`, and TypeScript catches typos and wrong arguments. There is nothing to configure: the type flows from the `import()`.

## Preloading

When `url` is known, `useWasm()` asks React to preload the binary. During server rendering, this adds a tag to the `<head>`:

```html
<link rel="preload" href="/assets/hello_bg-CSLcOxPe.wasm" as="fetch" crossorigin="" type="application/wasm"/>
```

The browser starts downloading the `.wasm` file as soon as it reads the `<head>`, in parallel with your JavaScript, instead of waiting for React to run. In the benchmarks, with 100 ms of network latency, the first Rust result appeared after **224 ms instead of 330 ms (−32%)**.

`as="fetch"` and `crossorigin` match how the binary is actually requested later (with `fetch()`), so the browser reuses the preloaded response instead of downloading the file twice.

In a client-only app the preload is added during the first render: a small head start, since there is no server HTML to put it in.

### Getting the URL

With Vite, import the binary with the `?url` suffix. Vite copies the file to `dist/assets`, adds a content hash to its name, and gives you the final URL, the same one in the client and server builds:

```ts
import url from "./pkg/hello_bg.wasm?url";
```

With webpack 5 or Rspack, the `new URL()` pattern emits the file and gives you its URL (check that your server build produces the same public URL):

```ts
const url = new URL("./pkg/hello_bg.wasm", import.meta.url).href;
```

Without `url`, everything still works; wasm-bindgen's glue finds the binary next to itself, but there is no preload.

## Handling errors

If the module fails to load (network error, 404, invalid binary), `useWasm()` throws the error during render, so it reaches the nearest **error boundary**. Calling `mod.load()` again retries. Do it when the boundary resets:

```tsx
import { ErrorBoundary } from "react-error-boundary";
import { hello } from "./wasm";

<ErrorBoundary
  onReset={() => void hello.load().catch(() => {})}
  fallbackRender={({ resetErrorBoundary }) => (
    <p>
      The Rust module could not load. <button onClick={resetErrorBoundary}>Try again</button>
    </p>
  )}
>
  <Stats data={data} />
</ErrorBoundary>;
```

`react-error-boundary` is optional; any error boundary works. What matters is calling `load()` before the children render again.

## Suspense instead

Prefer Suspense to checking for `undefined`? React's `use()` works with `mod.load()`, which always returns the same promise:

```tsx
"use client";
import { Suspense, use } from "react";
import { hello } from "./wasm";

function Stats({ data }: { data: Float64Array }) {
  const rust = use(hello.load()); // suspends until loaded
  return <p>Mean: {rust.mean(data)}</p>;
}

export function StatsPanel({ data }: { data: Float64Array }) {
  return (
    <Suspense fallback={<p>Loading…</p>}>
      <Stats data={data} />
    </Suspense>
  );
}
```

> **Warning:** Use this pattern only in components that render in the browser. During server rendering, `load()` would try to fetch the binary on the server. `useWasm()` is the right choice for server-rendered components.

## Outside React

A declared module is a plain object, usable anywhere:

```ts
import { hello } from "./wasm";

// Load on demand, for example in an event handler.
button.addEventListener("click", async () => {
  const rust = await hello.load();
  output.textContent = rust.greet("you");
});

// Read synchronously: the exports, or undefined if not loaded yet.
const maybeRust = hello.get();
```

`load()` and `useWasm()` share the same state: loading in one place makes the module available everywhere.

## Load early

By default, loading starts with the first component that needs the module. To start it as soon as your app's JavaScript runs, call `load()` at module level, in the browser only:

```ts
export const hello = wasm(() => import("./pkg/hello.js"), { url });

if (typeof window !== "undefined") {
  hello.load().catch(() => {}); // a failure still reaches useWasm() and your error boundary
}
```

## wasm-bindgen targets

- **`--target web`** (recommended): the glue exports an async `init` function as its default export. active-react calls it for you, with `{ module_or_path: url }` when you gave a `url`.
- **`--target bundler`**: the bundler instantiates the binary itself (Vite needs a plugin for this). The module is used as is, without `init`, and there is no preload.

For a `.wasm` file without any glue, pass its URL instead of a function: see [raw WebAssembly](../raw-wasm/).

## Testing

In unit tests, declare a fake module with plain functions. A loader returning an object without a default `init` export is used as is:

```ts
import { wasm } from "active-react";

export const fakeHello = wasm(async () => ({
  greet: (name: string) => `Hello ${name}`,
  mean: (values: Float64Array) => values.reduce((a, b) => a + b, 0) / values.length,
}));
```

## The Wasm object

`wasm()` returns a `Wasm<T>`, where `T` is the type of the exports:

```ts
interface Wasm<T> {
  /** URL of the .wasm binary when known; preloaded by useWasm. */
  readonly url?: string;
  /** Starts loading once and resolves with the exports. Calling it again after a failure retries. */
  load(): Promise<T>;
  /** The exports once loaded, undefined before; throws if loading failed. */
  get(): T | undefined;
  /** Notifies listener when loading settles; starts loading. */
  subscribe(listener: () => void): () => void;
}
```

`subscribe` and `get` are what `useWasm()` passes to React's `useSyncExternalStore`. You can use them to connect a module to another state library.
