---

A Progressive Web App is a website that phones and computers can install: it gets an icon on the home screen, opens full screen without the browser bar, and keeps working when the network is down. Turning an active site into one takes two files and a few tags, all written in Rust by the `active::pwa` module:

- the **web app manifest** (`manifest.webmanifest`): the name, icons and colors of the installed app, written by `Manifest`;
- the **service worker** (`sw.js`): a small script the browser runs beside the pages, which saves the site on the device and answers from there when offline, generated by `ServiceWorker`;
- in every page, `Document::manifest` and `Document::service_worker` add the manifest link, the theme color, the home screen title and icon, and the line that registers the worker.

There is no JavaScript to write: browsers only run service workers as scripts, so active generates the worker from your Rust settings. This website is a PWA built this way: install it from your browser's menu, or turn on airplane mode and reload.

Service workers only run in a secure context: HTTPS, or `http://localhost` while you develop.

## The manifest

```rust
use active::pwa::Manifest;

fn manifest() -> Manifest {
    Manifest::new("Acme")
        .short_name("Acme")
        .description("Recipes from the Acme kitchen, even offline.")
        .start_url("/")
        .scope("/")
        .id("/")
        .theme_color("#6d4aff")
        .background_color("#0b0b10")
        .lang("en")
        .categories(["food"])
        .icon("/icon-192.png", "192x192", "image/png")
        .icon("/icon-512.png", "512x512", "image/png")
        .maskable_icon("/icon-maskable-512.png", "512x512", "image/png")
        .icon("/favicon.svg", "any", "image/svg+xml")
}

let json = manifest().to_json();
assert!(json.starts_with(r#"{"name":"Acme","short_name":"Acme""#));
assert!(json.contains(r#""start_url":"/","scope":"/","display":"standalone""#));
```

| Method | Effect |
| --- | --- |
| `Manifest::new(name)` | a manifest named `name`, opening at `./` in `standalone` mode (full screen, no browser bar) |
| `.short_name(name)` | the name under the icon; 12 characters at most look good |
| `.description(text)` | what the app does |
| `.start_url(url)` | the page the icon opens (`./` by default: relative to the manifest) |
| `.scope(url)` | the URLs that belong to the app (by default the manifest's folder) |
| `.id(url)` | the identity of the app (defaults to `start_url`); keep it stable once published |
| `.display(mode)` | `standalone` (default), `fullscreen`, `minimal-ui` or `browser` |
| `.orientation(value)` | `portrait`, `landscape`, `any`… |
| `.theme_color(color)` | the color of the status bar and of the window title (`#000000` by default) |
| `.background_color(color)` | the color of the splash screen while the app starts (`#ffffff` by default) |
| `.lang(code)` | the language of the texts: `en`, `fr`, `en-US`… |
| `.categories(list)` | store categories: `productivity`, `education`… |
| `.icon(src, sizes, mime)` | an icon: `"192x192"`, `"512x512"`, or `"any"` for an SVG |
| `.maskable_icon(src, sizes, mime)` | an icon drawn for round and squircle masks (see [Icons](#icons)) |
| `.to_json()` | the manifest as JSON, to serve at `/manifest.webmanifest` |

`name()`, `theme()` and `icons()` read the values back. Every string is escaped, so names and descriptions can contain quotes or `<`.

The start URL must be a page that answers **200** and that the worker saves: a redirect cannot be replayed from the cache, so an app starting on a redirecting `/` would open on the offline page. This website starts on `/en/` for that reason, since its `/` redirects to the visitor's language.

## The service worker

```rust
use active::pwa::ServiceWorker;

fn worker() -> ServiceWorker {
    ServiceWorker::new("acme", "2026-10-10.1")
        .precache([
            "/",
            "/static/app.css",
            "/pkg/acme.js",
            "/pkg/acme_bg.wasm",
            "/icon-192.png",
            "/icon-512.png",
        ])
        .offline_page("/offline/")
        .network_only("/api/")
}

let js = worker().to_js();
assert!(js.contains(r#"const CACHE = "acme-2026-10-10.1";"#));
assert!(js.contains(r#"const OFFLINE = "/offline/";"#));
assert!(js.contains(r#"const NETWORK_ONLY = ["/api/"];"#));
```

| Method | Effect |
| --- | --- |
| `ServiceWorker::new(name, version)` | a worker whose cache is named `{name}-{version}` |
| `.precache(urls)` | URLs saved when the worker installs, available offline from the first visit; call it as many times as needed |
| `.offline_page(url)` | the page shown when a page was never saved and the network is down; it is precached too |
| `.network_only(prefix)` | URLs whose path starts with `prefix` always go to the network (an API, a live feed…) |
| `.cache_name()` | `{name}-{version}` |
| `.to_js()` | the script, to serve at the root of the site |

### Strategy

The generated worker handles the `GET` requests of its own site and leaves everything else (forms that `POST`, other sites) to the browser:

- **Pages** (navigations) come from the **network first**, so visitors online always see the latest version, and each page received is saved. Offline, the saved copy is shown, else the offline page.
- **Other files** of the site (stylesheet, WebAssembly bundle, images, fonts, data fetched by the page) come from the **cache at once**, and are refreshed in the background for the next visit. A file that is not saved yet comes from the network and is saved.
- **`network_only` prefixes** are never cached. The prefix is compared with the path of the URL, so it includes the base path of the site if it has one.
- **A new version** (another `version` string) installs itself, downloads its precache list, takes over the open pages at once and deletes the caches of older versions with the same `name`.

### What to precache

Precache what a visitor needs to open the app offline: the start page and the main pages, the stylesheet, the WebAssembly bundle (the JavaScript loader and the `.wasm` file), the fonts and the icons. Use **the exact URLs the pages use**: the cache matches query strings, so if a page loads `/static/app.css?v=3f2a…`, precache that URL and not `/static/app.css`. Leave out files that do not exist: one failed download cancels the installation.

### Choosing the version

Change `version` with every deployment that changes something the worker saves; otherwise browsers keep the old worker and its old files. A hash of those files does it automatically, the same FNV-1a hash this website uses for its `?v=` URLs (see [Documents, Long-term caching](../documents/#long-term-caching)):

```rust
/// A short hash of everything the worker saves: new files, new worker.
fn version(files: &[&[u8]]) -> String {
    let hash = files.iter().flat_map(|f| f.iter()).fold(0xcbf2_9ce4_8422_2325_u64, |h, b| {
        (h ^ u64::from(*b)).wrapping_mul(0x0100_0000_01b3)
    });
    format!("{hash:016x}")[..10].to_string()
}

let v1 = version(&[b"body{color:red}", b"\0asm"]);
assert_ne!(v1, version(&[b"body{color:blue}", b"\0asm"]));
```

This website hashes the precached pages as rendered, the manifest and every static file, so any change to them publishes a new worker.

## The tags of every page

```rust
use active::pwa::Manifest;
use active::prelude::*;

let manifest = Manifest::new("Acme")
    .short_name("Acme")
    .theme_color("#6d4aff")
    .icon("/icon-192.png", "192x192", "image/png")
    .icon("/icon-512.png", "512x512", "image/png");
let html = Document::new(h1().text("Recipes"))
    .manifest("/manifest.webmanifest", &manifest)
    .service_worker("/sw.js")
    .render();
assert!(html.contains(r#"<link rel="manifest" href="/manifest.webmanifest"/>"#));
assert!(html.contains(r##"<meta name="theme-color" content="#6d4aff"/>"##));
assert!(html.contains(r#"<link rel="apple-touch-icon" href="/icon-512.png"/>"#));
assert!(html.contains(r#"navigator.serviceWorker.register("/sw.js")"#));
```

`.manifest(href, &manifest)` writes into the `<head>`:

- `<link rel="manifest">` pointing to `href`, where you serve `manifest.to_json()`;
- `<meta name="theme-color">` with the manifest's theme color (do not write your own);
- `mobile-web-app-capable`, `apple-mobile-web-app-capable` and `apple-mobile-web-app-title` (the short name, else the name), for browsers that read meta tags rather than the manifest;
- `<link rel="apple-touch-icon">` with the largest PNG icon of purpose `any`: iOS uses it for the home screen and ignores the manifest's icons.

`.service_worker(url)` adds one small inline script that registers the worker once the page has loaded, so it never slows the first display:

```html
<script>if("serviceWorker"in navigator)addEventListener("load",()=>navigator.serviceWorker.register("/sw.js"))</script>
```

Call both on **every** page, so that the app can be installed from any of them. Both are shortcuts for [`.head(...)`](../documents/#the-builder); the URL is escaped safely.

### Content-Security-Policy

If your server sends a Content-Security-Policy without `'unsafe-inline'`, allow the registration script by its hash: compute the SHA-256 of `active::pwa::register_script(url)` (the exact text between the `<script>` tags), encode it in base64 and add `'sha256-…'` to `script-src`, as you do for other inline scripts. The worker and the manifest are files of your own site: keep `'self'` in `script-src` (or `worker-src`) and in `default-src` (or `manifest-src`).

## Serving the files

The manifest must be served as `application/manifest+json` and the worker as JavaScript. Serve the worker with `Cache-Control: no-cache`, so that browsers see a new version as soon as it is deployed. With [Axum](../axum/):

```rust
use active::pwa::{Manifest, ServiceWorker};
use axum::{Router, http::header, response::IntoResponse, routing::get};

fn manifest() -> Manifest {
    Manifest::new("Acme").start_url("/").icon("/icon-512.png", "512x512", "image/png")
}

fn worker() -> ServiceWorker {
    ServiceWorker::new("acme", env!("CARGO_PKG_VERSION")).precache(["/", "/icon-512.png"])
}

async fn manifest_file() -> impl IntoResponse {
    (
        [(header::CONTENT_TYPE, "application/manifest+json"), (header::CACHE_CONTROL, "no-cache")],
        manifest().to_json(),
    )
}

async fn worker_file() -> impl IntoResponse {
    (
        [(header::CONTENT_TYPE, "text/javascript; charset=utf-8"), (header::CACHE_CONTROL, "no-cache")],
        worker().to_js(),
    )
}

let app: Router = Router::new()
    .route("/manifest.webmanifest", get(manifest_file))
    .route("/sw.js", get(worker_file));
```

A worker controls the pages under its own folder: serve `sw.js` at the root of the site (`/sw.js`), not in `/static/` or `/pkg/`, or it would only handle the URLs below that folder.

## Static sites and base paths

A [static site](../static-site/) writes both files next to its pages:

```rust
use std::path::Path;

use active::pwa::{Manifest, ServiceWorker};

/// "" at the root of a domain, "/my-blog" for a GitHub Pages project site.
const BASE: &str = "/my-blog";

fn write_pwa(dist: &Path) -> std::io::Result<()> {
    let manifest = Manifest::new("My blog")
        .start_url(format!("{BASE}/"))
        .scope(format!("{BASE}/"))
        .id(format!("{BASE}/"))
        .icon(format!("{BASE}/icon-512.png"), "512x512", "image/png");
    let worker = ServiceWorker::new("my-blog", "1")
        .precache([format!("{BASE}/"), format!("{BASE}/app.css")])
        .offline_page(format!("{BASE}/offline/"));
    std::fs::write(dist.join("manifest.webmanifest"), manifest.to_json())?;
    std::fs::write(dist.join("sw.js"), worker.to_js())
}
```

Every URL in the manifest, in the worker and in the page tags (`.manifest(&format!("{BASE}/manifest.webmanifest"), …)`, `.service_worker(&format!("{BASE}/sw.js"))`) carries the base path. Written at the top of the export, `sw.js` is served at `/my-blog/sw.js`, so its scope is `/my-blog/`. GitHub Pages serves both files with the right types, over HTTPS (see [GitHub Pages](../deploy-pages/)).

## Icons

Phones want at least a **192×192** and a **512×512** PNG. Add a **maskable** 512×512 icon too: Android cuts icons into circles or squircles, so a maskable icon fills the whole square with the background color and keeps the logo inside the central circle, 80% of the side. Keep the SVG logo as an extra icon of size `any` for desktops. The largest PNG icon of purpose `any` becomes the Apple touch icon.

Draw the PNGs once from your SVG logo with any SVG renderer (resvg, Inkscape, or a headless browser that screenshots the SVG in a page of the exact size) and commit them with the site: nothing has to run at build time. This website's icons are rendered from `site/static/favicon.svg` this way.

## Testing offline

- **In Chrome**, open DevTools → **Application**: *Manifest* shows the parsed manifest, its icons and installability errors; *Service workers* the worker's state, with **Update on reload** for development; *Cache storage* the `{name}-{version}` cache and the URLs it holds. Then tick **Offline** in the *Network* tab and reload, and open a page you never visited: you get the offline page.
- **Automated**, with a headless browser such as Playwright: load a page, wait for `navigator.serviceWorker.ready`, then **stop the server** and navigate: the precached pages and the pages already visited render, with their islands; any other page shows the offline page. Stopping the server is more faithful than the browser's offline emulation, which may not cut the requests the worker makes itself.
- **In Rust tests**, check what you serve: the manifest's URLs and the worker's precache list.

```rust
use active::pwa::ServiceWorker;

let js = ServiceWorker::new("acme", "1")
    .precache(["/", "/static/app.css?v=3f2a"])
    .offline_page("/offline/")
    .to_js();
assert!(js.contains(r#"const PRECACHE = ["/","/static/app.css?v=3f2a","/offline/"];"#));
```

## This website

The website you are reading does all of the above, in [`site/src/server/pwa.rs`](https://github.com/maxlestage/Active/blob/master/site/src/server/pwa.rs):

- `/manifest.webmanifest` opens the app on `/en/`, with the 192, 512 and maskable PNG icons and the SVG logo;
- `/sw.js` precaches the three home pages, the stylesheet and the WebAssembly bundle with their `?v=` URLs, the fonts and the icons; its version is a hash of all of them;
- `/offline/` is the offline page, in the three languages since the worker has only one;
- every page calls `.manifest(...)` and `.service_worker(...)`, and the static export for GitHub Pages writes `manifest.webmanifest`, `sw.js` and `offline/index.html` with `/Active` in every URL.
